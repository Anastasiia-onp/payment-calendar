# Платёжный календарь

Прогноз денежных средств на 13 недель с поиском кассовых разрывов.

Отвечает на три вопроса финансиста: **когда кончатся деньги**, **сколько не хватит**
и **что подвинуть, чтобы хватило**.

[Посмотреть дашборд на демо-данных](https://claude.ai/artifact/FygPugsKxEvvToqJQkoMdq)

---

## Зачем

Компания может быть прибыльной и при этом не иметь денег на зарплату в конкретную
пятницу: выручка начисляется по актам, а деньги приходят через 30–60 дней.

Без календаря нехватку видят в день платежа, а не за три недели до него.
Ведение календаря вручную занимает несколько часов в неделю и разваливается
при первом же переносе срока.

Инструмент собирает календарь за одну команду и показывает не только проблему,
но и способы её закрыть.

## Что получается на выходе

| Файл | Что внутри |
|---|---|
| `02_calc/Платежный_календарь_<дата>.xlsx` | Календарь по неделям живыми формулами, сводный реестр, лист разрывов, контрольные суммы |
| `04_dashboard/Платежный_календарь_Дашборд.html` | Интерактивный дашборд: график остатка, перенос платежей, фильтр по проектам |
| `03_output/<дата>_Платежный_календарь_Выводы.md` | Выводы для руководителя: факт → причина → решение |

## Быстрый старт

Нужен Python 3 и библиотека `openpyxl`:

```bash
pip install openpyxl
```

Дальше три команды:

```bash
# 1. создать форму реестра (шаблон + демо-файл с условными данными)
python scripts/make_template.py

# 2. посчитать календарь
python scripts/build_calendar.py "01_input/Реестр_обязательств_ДЕМО.xlsx"

# 3. собрать дашборд и выводы
python scripts/make_dashboard.py "01_input/Реестр_обязательств_ДЕМО.xlsx"
python scripts/make_conclusions.py "01_input/Реестр_обязательств_ДЕМО.xlsx"
```

Дашборд открывается двойным щелчком, интернет не нужен.

## Пользовательский сценарий

**Понедельник, утро. Нужно понять, доживём ли до конца квартала.**

1. Открыть `01_input/Реестр_обязательств_Шаблон.xlsx`.
2. На листе **«Счета и лимиты»** вписать остатки по всем расчётным счетам
   и свободные кредитные лимиты.
3. На листе **«Параметры»** поставить дату начала прогноза — ближайший понедельник.
   Остаток подтянется со счетов формулой.
4. На листе **«Регулярные платежи»** описать правилами то, что повторяется:
   ФОТ, аренду, лизинг, проценты. Одна строка — одно правило на весь горизонт.
5. На листе **«Реестр»** внести разовое: поступления по договорам, счета подрядчиков,
   налоги (суммы меняются от месяца к месяцу — их правилом не опишешь).
6. Сохранить файл в `01_input/`.
7. Запустить три команды из быстрого старта.
8. Открыть дашборд, посмотреть, где провал, и отметить галочками платежи,
   которые готовы перенести. График пересчитается сразу.
9. Выводы из `03_output/` отправить руководителю.

**Если есть выгрузка счетов к оплате из учётной системы** — шаг между 6 и 7:

```bash
python scripts/import_registry.py "01_input/<выгрузка>.xlsx"
python scripts/build_calendar.py "01_input/<реестр>.xlsx" --import "02_calc/Импорт_<дата>.xlsx"
```

Импортёр сам найдёт шапку таблицы, сопоставит колонки с полями реестра
и сверится с итоговой строкой выгрузки. Соответствия запоминаются —
следующая выгрузка того же вида разберётся без настройки.

## Как это считает

**Горизонт** — 13 недель: стандарт казначейского прогноза, квартал вперёд.

Число недель меняется на листе «Параметры», но растягивать недельный календарь
дальше квартала не стоит, и причина не в коде. Данные асимметричны по дальности:
зарплата, налоги и аренда известны на год вперёд — это правила; счета подрядчиков
видны на 4–8 недель; поступления по договорам — на квартал, дальше договоров
ещё нет. Поставишь 26 недель — получишь не прогноз, а картину «все платят,
никто не платит нам», с разрывом, которого в реальности не будет.

Пример такого расчёта лежит в `02_calc/Проверка_горизонт_26_недель.xlsx`.

Правильный способ смотреть дальше — два уровня: 13 недель понедельно (этот
инструмент) и 4–12 месяцев помесячно по бюджету (месячный БДДС, другая точность
и другое назначение). Для горизонта в полгода понадобится колонка «Вероятность
поступления» — без неё дальние недели выходят односторонними.

Текущий режим работы — скользящий прогноз: каждый понедельник дата начала
сдвигается на неделю вперёд, горизонт остаётся 13 недель и всегда свежий.

**Остаток** считается нарастающим итогом: остаток на начало недели + поступления −
платежи = остаток на конец, он же начало следующей.

**Кассовый разрыв** — неделя с отрицательным остатком. Отдельно отмечаются недели
ниже порога тревоги: денег формально хватает, но запаса нет.

**Приоритеты платежей** подтягиваются по статье ДДС:

| Приоритет | Что входит | Можно двигать |
|---|---|---|
| 1 | Налоги, ФОТ, взносы, погашение кредита | Нет: штрафы и пени |
| 2 | Подрядчики, материалы, аренда, лизинг | По договорённости |
| 3 | Командировки, обучение, прочие расходы | Да, без последствий |

**Повторяющиеся платежи** описываются правилом, а не строками. Даты, попавшие
на выходной или праздник, переносятся: зарплата и аренда — на предыдущий рабочий
день, налоги и проценты — на следующий.

## Принципы, которые соблюдаются в коде

1. **Исходный файл не изменяется.** Результат — всегда новый файл с датой в имени.
2. **Ничего не додумывается.** Нет суммы или даты — строка не попадает в расчёт
   и выводится в замечаниях с причиной.
3. **В Excel пишутся формулы, а не значения.** Поменяли сумму в реестре — календарь
   пересчитался сам.
4. **Двойной счёт.** Python считает контрольные цифры, Excel — формулами.
   Расхождение означает ошибку, и оно будет видно.
5. **Перенос платежа предлагается, но не применяется.** Решение принимает финансист.

## Чего инструмент не делает

- Не учитывает просроченную задолженность прошлых периодов, если её нет в реестре.
- Не оценивает вероятность поступления: статус «План» считается подтверждённым.
- Работает только в рублях.
- Не ходит в 1С и банк напрямую — работает с выгрузками.
