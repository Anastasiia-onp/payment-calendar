# Платёжный календарь

Инструмент отвечает на три вопроса: **когда кончатся деньги**, **сколько не хватит** и **что подвинуть, чтобы хватило**.

Рабочая папка проекта — `payment-calendar/`.

## Когда применять

- «Хватит ли денег до конца квартала?»
- «Когда у нас будет кассовый разрыв?»
- «Можем ли мы сейчас заплатить подрядчику 2 млн?»
- «Что перенести, чтобы выплатить зарплату вовремя?»
- Нужен платёжный календарь, казначейский прогноз, план платежей.

## Главные правила

1. **Исходный файл не изменяется никогда.** Все результаты — новые файлы с датой в имени.
2. **Ничего не додумывать.** Нет суммы или даты — строка не попадает в расчёт и уходит в замечания. Писать «данных нет», а не подставлять среднее.
3. **Расчёты формулами.** В Excel пишутся формулы, не значения. Python считает контрольные цифры и сверяется с ними.
4. **Перенос платежа предлагается, но не применяется.** Решение за финансистом.

## Порядок работы

### 1. Уточнить исходные данные

Спросить, если неизвестно:
- какой файл реестра использовать;
- есть ли выгрузка счетов к оплате для импорта;
- дата начала прогноза (обычно ближайший понедельник).

Если файла реестра нет — создать форму:

```bash
python scripts/make_template.py
```

Создаёт в `01_input/` пустой шаблон и демо-файл с условными данными.

### 2. Проверить реестр

Прочитать лист «Параметры»: заполнена ли дата начала и порог тревоги.
Лист «Счета и лимиты»: остатки по счетам и свободные кредитные лимиты.

Если дата начала не заполнена — расчёт не запускать, сначала спросить её.

### 3. Импортировать счета, если есть выгрузка

```bash
python scripts/import_registry.py <файл выгрузки>
python scripts/import_registry.py <файл> --type Поступление
python scripts/import_registry.py <файл> --map "Контрагент плательщик=контрагент"
```

Импортёр сам находит шапку таблицы и сопоставляет колонки. Показать пользователю:
какие колонки распознаны, сколько строк импортировано, что отбраковано и почему,
сошлась ли контрольная сумма с итогом выгрузки.

### 4. Посчитать календарь

```bash
python scripts/build_calendar.py 01_input/<реестр>.xlsx
python scripts/build_calendar.py 01_input/<реестр>.xlsx --import 02_calc/Импорт_<дата>.xlsx
```

Создаёт `02_calc/Платежный_календарь_<дата>.xlsx`: листы «Календарь», «Сводный реестр»,
«Разрывы», «Параметры и проверки».

### 5. Собрать дашборд

```bash
python scripts/make_dashboard.py 01_input/<реестр>.xlsx
python scripts/make_dashboard.py 01_input/<реестр>.xlsx --anon
```

`--anon` обезличивает контрагентов — обязательно перед публикацией или показом вовне.

Дашборд открывается в браузере, работает без интернета. На нём можно менять остаток
на старте, переносить платежи приоритета 3 и фильтровать по проекту.

### 6. Сформировать выводы

```bash
python scripts/make_conclusions.py 01_input/<реестр>.xlsx
```

Создаёт `03_output/<дата>_Платежный_календарь_Выводы.md` по схеме
факт → причина → решение.

### 7. Доложить результат

Отвечать в таком порядке:

1. **Главное одной фразой**: есть разрыв или нет, когда и сколько.
2. **Таблица недель** с остатком и состоянием.
3. **Откуда дефицит**: крупнейшие платежи проблемных недель.
4. **Чем закрыть**: перенос приоритета 3 → отсрочка у подрядчиков → кредитный лимит.
5. **Замечания к данным** — всегда, даже если их нет: так и сказать, что замечаний нет.

Суммы — в рублях, с разделением разрядов. Округление только в подаче результата.

## Как устроены приоритеты

| Приоритет | Что входит | Можно ли двигать |
|---|---|---|
| 1 | Налоги, ФОТ, страховые взносы, погашение кредита | Нет: штрафы, пени, остановка работы |
| 2 | Подрядчики, материалы, аренда, лизинг | Только по договорённости |
| 3 | Командировки, обучение, прочие расходы | Да, без последствий |

Приоритет подтягивается из справочника статей по статье ДДС. Для конкретного
платежа его можно переписать вручную в реестре.

## Повторяющиеся платежи

Лист «Регулярные платежи» — правила, а не строки: сумма, периодичность, день месяца,
период действия, правило переноса с выходного.

Перенос с нерабочего дня:
- **Раньше** — зарплата, аренда, лизинг (людям платят до выходных);
- **Позже** — налоги, взносы, проценты (по НК срок сдвигается на следующий рабочий день).

Нерабочие дни правятся на листе «Справочники». Переносы выходных на будущий год
нужно сверять с производственным календарём — предупредить об этом пользователя.

Проверить, во что развернутся правила, до расчёта:

```bash
python scripts/expand_recurring.py 01_input/<реестр>.xlsx
```

## Чего инструмент не делает

- Не учитывает просроченную задолженность прошлых периодов, если её нет в реестре.
- Не оценивает вероятность поступления: статус «План» считается как подтверждённый.
- Работает только в рублях.
- Не применяет переносы автоматически.

Об этих границах говорить сразу, если пользователь делает на основании расчёта
далеко идущие выводы.
