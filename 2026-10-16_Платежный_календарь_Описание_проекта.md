# Платёжный календарь

Итоговый проект курса по вайб-кодингу. Версия описания: 2026-10-16.

---

## 1. Название

**Платёжный календарь** — инструмент прогноза денежных средств и поиска кассовых разрывов на 13 недель.

---

## 2. Проблема

Компания может быть прибыльной и при этом не иметь денег на выплату зарплаты в конкретную пятницу. Прибыль и деньги — разные вещи: выручка начисляется по актам, а деньги приходят через 30–60 дней.

Что происходит без платёжного календаря:
- обязательства разбросаны по договорам, счетам, таблицам и голове бухгалтера;
- нехватку денег видят в день платежа, а не за три недели до него;
- решение «кому платить первым» принимается в спешке, а не по приоритету;
- руководитель спрашивает «деньги на закупку есть?» — ответа сразу нет.

Что происходит, когда календарь ведут вручную:
- сборка занимает несколько часов каждую неделю;
- при каждом изменении срока календарь пересобирается заново;
- ошибки в формулах находятся уже после того, как отчёт ушёл руководителю.

**Цена ошибки:** просроченный платёж = пени по договору, штраф по налогам, задержка зарплаты, испорченные отношения с поставщиком.

---

## 3. Пользователь

**Основной:** финансовый менеджер, финансовый контроллер, финансовый директор малой и средней компании (строительство, инжиниринг, поставки) — тот, кто отвечает за то, чтобы деньги на счёте были.

**Вторичный:** собственник или генеральный директор — получатель результата. Ему нужен не файл, а ответ: хватит денег или нет, и что делать.

**Условия работы пользователя:** работает в Excel, не программирует, ведёт учёт в 1С, выгрузки делает вручную. Инструмент должен работать без установки сложного ПО и выдавать файл, который можно открыть и проверить.

---

## 4. Основная функция

Одна команда превращает реестр обязательств в прогноз денежных средств с подсветкой кассовых разрывов.

### Вход
| Что | Описание |
|---|---|
| Реестр обязательств | Excel-файл: контрагент, сумма, срок платежа, статья, тип (поступление/платёж) |
| Остаток денежных средств | Остаток на счетах на дату начала прогноза |
| Дата начала | Первый день горизонта прогноза |

### Обработка
1. Чтение реестра, проверка данных — пропуски, нули, отрицательные суммы, некорректные даты.
2. Разнесение каждого обязательства по неделям горизонта.
3. Группировка по статьям: поступления, налоги, ФОТ, подрядчики, материалы, прочее.
4. Расчёт по каждой неделе: поступления − платежи = чистый поток; остаток на начало + чистый поток = остаток на конец.
5. Поиск кассовых разрывов — недель с отрицательным остатком; расчёт суммы и даты разрыва.
6. Присвоение приоритета платежам: 1 — налоги и ФОТ, 2 — подрядчики и материалы, 3 — прочее.
7. Подбор вариантов закрытия разрыва: какие платежи приоритета 3 перенести, чтобы остаток не ушёл в минус.

### Выход
1. **Excel-файл** — все расчёты живыми формулами, без «забитых» чисел.
2. **Дашборд** — график остатка по неделям, красные зоны разрывов, ключевые цифры.
3. **Выводы** — текст: где разрыв, какого размера, из-за чего, что сделать.

## 5. Формат результата

### Excel-файл `Платежный_календарь_ГГГГ-ММ-ДД.xlsx`

| Лист | Содержимое |
|---|---|
| `Параметры` | Дата начала, остаток на старте, горизонт, порог тревоги |
| `Реестр` | Исходные обязательства + расчётный номер недели |
| `Календарь` | Недели в столбцах, статьи в строках, итоги формулами, остаток нарастающим итогом |
| `Разрывы` | Недели с дефицитом: дата, сумма нехватки, что можно перенести |

Расчётные ячейки — формулы `СУММЕСЛИМН`, `ЕСЛИ`, ссылки на `Реестр`. Пользователь меняет сумму в реестре — календарь пересчитывается сам.

### Интерактивный дашборд `Платежный_календарь_Дашборд.html`

Это и есть интерфейс проекта — не картинка, а рабочая панель.

Показывает:
- линию остатка денежных средств по 13 неделям, нулевую линию, красную заливку зон дефицита;
- столбцы поступлений и платежей по неделям;
- плитки: минимальный остаток за горизонт, дата первого разрыва, максимальная сумма разрыва, итоги.

Позволяет:
- менять стартовый остаток ползунком и видеть, как смещается точка разрыва;
- галочкой переносить платёж на другую неделю и сразу видеть, закрылся ли разрыв;
- фильтровать статьи расходов и смотреть вклад каждой в дефицит;
- сбрасывать все изменения к исходному расчёту одной кнопкой.

Открывается двойным щелчком, работает без интернета и установки. Все пересчёты — в браузере.

### Выводы `ГГГГ-ММ-ДД_Платежный_календарь_Выводы.md`
Структура: факт → причина → управленческое решение. Без выдуманных цифр; при нехватке данных пишется «данных нет».

## 6. Минимальный функционал

### Первая версия (MVP)
- [ ] Чтение реестра обязательств из Excel
- [ ] Проверка данных и отчёт об аномалиях
- [ ] Горизонт 13 недель, шаг — неделя
- [ ] Расчёт остатка нарастающим итогом формулами Excel
- [ ] Определение кассовых разрывов: дата, сумма
- [ ] Приоритеты платежей (3 уровня)
- [ ] Варианты закрытия разрыва переносом платежей приоритета 3
- [ ] HTML-дашборд
- [ ] Файл выводов
- [ ] Скилл Claude Code: запуск одной командой
- [ ] README с инструкцией запуска и пользовательским сценарием
- [ ] Публикация в репозиторий GitHub
- [ ] Скилл для коллег: развернуть такой же инструмент у себя

### Ограничения MVP (сознательные)
| Ограничение | Почему так |
|---|---|
| Только рубли | Мультивалютность требует курсов и переоценки — отдельная задача |
| Горизонт фиксирован: 13 недель | Стандарт казначейского прогноза; дальше данные недостоверны |
| Один файл-реестр на входе | Интеграция с 1С и банком — не MVP |
| Нет сценариев «что если» | Усложняет модель, не нужно для первого результата |
| Перенос платежей предлагается, но не применяется автоматически | Решение о переносе — за финансистом, не за программой |
| Исходный файл не изменяется никогда | Результат пишется в новый файл с датой в имени |

### Планы развития (вне MVP)
- Сценарии: оптимистичный / базовый / пессимистичный.
- План-факт по платёжному календарю: что планировали — что заплатили.
- Автоподтягивание графиков платежей из договоров.
- Учёт просроченной дебиторской задолженности с коэффициентом собираемости.
- Мультивалютность.

## 7. Технологии

| Слой | Инструмент | Зачем |
|---|---|---|
| Среда | Claude Code | Запуск, оркестрация, формирование выводов |
| Логика | Python 3 | Чтение реестра, проверки, расчёт недель и разрывов |
| Excel | openpyxl | Запись листов и **формул**, а не готовых значений |
| Данные | pandas | Группировки и сводные расчёты при подготовке |
| Интерфейс | HTML + CSS + JavaScript, Chart.js | Интерактивный дашборд: пересчёт в браузере, офлайн, без сервера |
| Публикация | GitHub + артефакт Claude | Репозиторий с кодом и рабочая ссылка на дашборд |
| Упаковка | Skill Claude Code (Markdown + Python-скрипт) | Повторный запуск одной командой |
| Форматы | `.xlsx`, `.html`, `.md` | Привычные для финансиста, ничего не нужно устанавливать |

**Принцип по расчётам:** Python считает контрольные значения для проверки, но в Excel пишутся формулы. Итог должен сходиться двумя путями — расчётом Python и пересчётом Excel. Расхождение означает ошибку и выводится явно.

---

## 8. Критерии готовности

Проект считается завершённым, когда:
1. Скилл запускается одной командой и отрабатывает без ошибок на реальном реестре.
2. Итоги Excel сходятся с контрольным расчётом Python до копейки.
3. Исходный файл не изменён.
4. Дашборд открывается в браузере и показывает те же цифры, что Excel.
5. Выводы читаются без погружения в технические детали.
6. По результату можно принять решение: платить или переносить.
